Raqib

A read only lookout over your AWS IAM. It finds the paths an attacker would take, and tells you how to close them.
GitHub Open a sample report

What it does

Raqib reads the IAM export your account already produces and reports the exposure in it: the privilege escalation paths a principal could walk, role trust policies that let the wrong people in, wildcard permissions on sensitive services, and, with a credential report, the stale keys and console logins without a second factor. Each finding says why it is exploitable and the change that closes it.

It never calls AWS and never touches your account. You hand it a file, and it reasons about that file offline. Nothing to trust it with beyond a JSON export you control.

A sample report

This is Raqib run against a deliberately weak example account. Open the live report.

Run it

aws iam get-account-authorization-details > export.json
python3 raqib.py audit export.json

# add credential findings, and write a shareable HTML report
aws iam generate-credential-report && aws iam get-credential-report --query Content --output text | base64 --decode > creds.csv
python3 raqib.py audit export.json --credential-report creds.csv -o report.html

# gate a pipeline: exit 1 on a critical or high finding
python3 raqib.py audit export.json --strict

It is a single zero dependency Python tool. It needs Python 3.8 or newer and nothing else.

What it looks for

  • The known IAM privilege escalation paths: rewriting an attached policy, attaching an administrator policy, setting a login password on another user, minting access keys, adding yourself to a group, rewriting a role trust policy, and passing a powerful role to EC2, Lambda, Glue, CloudFormation, CodeBuild, and more.
  • Role trust policies that are assumable by anyone, trust an external account, or federate without a condition.
  • Administrator by wildcard, and full control of sensitive services through a service wildcard.
  • Root access keys, console users without multi factor authentication, and access keys that are old and still active.
A finding says what a permission would allow, not that it was used. A clean report means the export named nothing these rules look for, not that the account is secure. Read only analysis by Raqib.
